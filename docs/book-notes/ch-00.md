# 현대 프론트엔드 개발은 복잡하다.

- 사용자의 예측 불가능한 행동
- 수시로 변하는 데이터
- 다양한 브라우저 환경
- 잦은 요구사항 변경

위 사항들이 하나의 화면 위에서 동시에 일어나고 서로에게 영향을 준다. 코드를 수정하다가 "이럴 바에는 새로 짜는것이 낫겠다"라는 생각이 든다면 복잡성은 이론이 아닌 현실 속 문제가 된 것이다.

> ![NOTE]
> 시간이 지나도 변하지 않는 소프트웨어 설계의 기본 원칙에 집중하자

### 이 책에서 다루는 내용

- 경험적으로 좋은 코드라는 확신은 있지만, "왜 좋은지" 구체적인 근거를 들어 설명하기 어려웠던 막막함
- 새로운 프레임워크 도입만으로는 해결되지 않는, 코드의 구조적인 개선을 통해 근본적인 문제를 해결하고 싶다는 갈증
- 테스트 코드의 필요성은 느끼지만 막상 작성하려고 하면 어디서부터 어떻게 시작해야 할지 몰라 막막했던 경험
- 오래되어 수정하기 어려운 레거시 코드를 마주했을 때 어떻게 점진적으로 개선할 수 있을지에 대한 고민

이 책은 명쾌한 정답을 찾기보다는 문제를 정의하고 해결책을 찾아가는 과정을 관찰하듯이 읽는다면 큰 도움이 된다.

### 읽고 나서 든 생각들

비록 서문에 불과하지만, 읽는 동안 많은 생각이 스쳐 지나갔다. 그동안 현대 프론트엔드 개발이 복잡한 이유를 단순히 ‘상태 관리’나 ‘데이터 흐름’의 문제로만 생각해왔다. 하지만 프론트엔드의 본질은 결국 사용자가 마주하는 화면이고, 브라우저라는 환경과 직결된다. 아직은 사용자의 예측 불가능한 행동을 직접 체감해 볼 기회가 없었지만, 그렇기에 오히려 서비스를 빠르게 배포해 실전의 변수들을 마주하고 싶다는 열망이 생겼다.

현업에서 잦은 요구사항 변경을 마주할 때마다, 어떻게 코드를 작성해야 변화에 유연한 설계를 만들 수 있을지 명확한 답을 내리지 못해 어려움을 겪고 있다. 지금도 마찬가지다. 이 책의 서론에서 나온 “시간이 지나도 변하지 않는 소프트웨어 설계의 기본 원칙에 집중하자”라는 문장은 큰 울림으로 다가왔다. 돌이켜보면 설계의 기본 원칙조차 제대로 이해하지 못한 상태였으니, 좋은 코드를 구분하거나 적절한 해결책을 찾지 못했던 것도 어쩌면 당연한 일이었는지도 모른다.

개발 도서를 읽을 때마다 느끼는 점은, 결국 가장 중요한 것은 현재 자신의 수준을 인정하고 배움의 자세로 꾸준히 임하는 것이라는 점이다. 취업이나 이직만을 위한 공부가 아니라, 스스로 흥미를 느끼고 궁금해서 찾아보는 과정 속에서 오래 지속할 수 있는 성장의 힘이 만들어진다고 생각한다.

그러니 이번에도 늘 그래왔듯이 파이팅했으면 좋겠다
